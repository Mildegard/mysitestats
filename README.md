# Статистика LiveInternet — автоматический сбор + графики

Простой набор файлов для автоматического ежедневного сбора статистики счётчика LiveInternet и отображения графиков на статической странице.

## Что внутри

| Файл | Назначение |
|------|------------|
| `collect.js` | Скрипт, который забирает данные с counter.yadro.ru |
| `data.json` | База данных (история по дням) |
| `stats.html` | Страница с графиками посещаемости |
| `.github/workflows/collect.yml` | Автоматический запуск каждый день через GitHub Actions |

## Быстрый старт (пошагово)

### 1. Создайте репозиторий на GitHub

1. Зайдите на [github.com](https://github.com) и войдите в аккаунт (или зарегистрируйтесь).
2. Нажмите кнопку **New** (или «+» → New repository).
3. Название репозитория — любое, например `my-site-stats`.
4. Поставьте галочку **Public** (или Private — тоже работает).
5. **Не** ставьте галочки «Add a README», «Add .gitignore» и т.п. — репозиторий должен быть пустым.
6. Нажмите **Create repository**.

### 2. Загрузите файлы

Самый простой способ — через веб-интерфейс:

1. На странице только что созданного репозитория нажмите **uploading an existing file**.
2. Перетащите **все** файлы из архива (включая папку `.github`).
3. Внизу напишите commit message, например: `Initial commit`.
4. Нажмите **Commit changes**.

> Важно: папка `.github` должна загрузиться вместе со всем содержимым.  
> Если браузер не даёт загрузить скрытые папки — используйте способ через Git (см. ниже).

#### Альтернатива: через Git (если умеете)

```bash
git clone https://github.com/ВАШ_ЛОГИН/my-site-stats.git
cd my-site-stats
# скопируйте сюда все файлы из архива
git add .
git commit -m "Initial commit"
git push
```

### 3. Укажите свой домен

1. Откройте файл `collect.js` в репозитории.
2. Найдите строку:
   ```js
   const DOMAIN = 'ВАШ_ДОМЕН.ru';
   ```
3. Замените `ВАШ_ДОМЕН.ru` на домен вашего сайта (без `http://` и без `www.`, если счётчик зарегистрирован без него).
4. Нажмите кнопку редактирования (карандаш), сохраните изменения (Commit changes).

### 4. Включите GitHub Actions

1. В репозитории перейдите на вкладку **Actions**.
2. Если GitHub спросит разрешение — нажмите **I understand my workflows, go ahead and enable them**.
3. Слева вы увидите workflow **Collect LiveInternet Stats**.
4. Нажмите на него, затем кнопку **Run workflow** → **Run workflow** (это ручной запуск для проверки).

Через 20–40 секунд внизу появится зелёная галочка — значит всё сработало.  
Файл `data.json` обновится автоматически.

### 5. Посмотрите графики

Откройте файл `stats.html` в репозитории и нажмите кнопку **Raw** (или откройте через GitHub Pages — см. ниже).

Либо просто скачайте `stats.html` + `data.json` и откройте `stats.html` в браузере локально.

## Как сделать страницу доступной по красивому адресу (GitHub Pages)

1. В репозитории зайдите в **Settings** → **Pages**.
2. В разделе **Source** выберите **Deploy from a branch**.
3. Branch: `main` (или `master`), папка `/ (root)`.
4. Нажмите **Save**.
5. Через 1–2 минуты страница будет доступна по адресу:
   ```
   https://ВАШ_ЛОГИН.github.io/my-site-stats/stats.html
   ```

## Расписание

По умолчанию сбор происходит **каждый день в 21:00 UTC**.

Это примерно:
- 00:00 по Москве (зимой)
- 23:00 по Москве (летом)

Чтобы изменить время — отредактируйте файл `.github/workflows/collect.yml`, строку:
```yaml
- cron: '0 21 * * *'
```

Можно проверить удобное время на сайте [crontab.guru](https://crontab.guru/).

## Ручной запуск

В любой момент можно запустить сбор вручную:

1. Вкладка **Actions**
2. Выберите **Collect LiveInternet Stats**
3. Кнопка **Run workflow** → **Run workflow**

## Что делать, если что-то не работает

- **Красный крестик в Actions**  
  Откройте упавший запуск → посмотрите лог. Чаще всего ошибка в домене (проверьте `collect.js`).

- **data.json пустой**  
  Запустите workflow вручную и подождите, пока он завершится.

- **На странице stats.html написано «Файл data.json не найден»**  
  Убедитесь, что `data.json` лежит в той же папке, что и `stats.html`.
